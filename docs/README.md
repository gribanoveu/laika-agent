# CLI-агент: требования и карта переноса

Проектные документы для **нового** продукта — CLI-кодинг-агента (в духе Claude Code /
opencode) с десктопным UI поверх того же ядра.

Этот каталог описывает продукт, которого ещё нет. К самому Alfa Atlas он отношения не
имеет, кроме одного: значительная часть агентного ядра здесь уже написана и оттуда
переносится. Что именно и в каком виде — в [04-reuse-map.md](04-reuse-map.md).

## Три тезиса, из которых растёт всё остальное

1. **Ядро не знает ни про CLI, ни про UI.** Агентный цикл уже написан так: сервис
   репортит наружу через sink (`Arc<dyn Fn(Event) + Send + Sync>`), а в Tauri-события
   это превращает только слой команд. Значит цикл переносится в отдельный крейт без
   переписывания — см. [03-architecture.md](03-architecture.md).
2. **Turn — это машина состояний, а не блокирующий вызов.** В Atlas уже есть пауза на
   подтверждении инструмента с возобновлением (`PendingApproval` → `ToolCallDecision`
   → `ResumePoint`). Это то, что позволяет одному и тому же turn'у обслуживать и
   интерактивный CLI, и headless-режим, и десктопный UI, и переподключение к сессии.
3. **Переносится инфраструктура вокруг цикла, а не список инструментов.** Инструменты
   в Atlas заточены под документацию (AsciiDoc-шаблоны, артефакты, диаграммы).
   Переносится форма границы `execute_tool`, гейтинг и логирование — конкретные
   инструменты пишутся под кодинг заново, кроме файловых.
