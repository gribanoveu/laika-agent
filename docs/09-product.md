# Atlas desktop: что это и чем отличается

Десктопный кодинг-агент для разработчика, который работает в своём репозитории: читает и
ищет код, правит файлы, запускает команды и тесты, показывает, что сделал. Одно окно на
Tauri, всё локально, модель — любой провайдер с OpenAI-совместимым API или Anthropic.

Документ описывает продукт **как он есть после этапов 0–7** плана переноса
([06-port-plan.md](06-port-plan.md)). Задуманное, но не сделанное вынесено в конец.

## Коротко: пять отличий

1. **Своя граница данных, проверяемая тестами.** Содержимое файлов уходит только к
   выбранному провайдеру. Это не обещание в README, а тесты: они падают, если сетевой код
   появился вне провайдера, если в зависимостях появилась телеметрия или в окне — `fetch`.
   У окна строгий CSP. Команды, уходящие в сеть, спрашивают разрешения **даже при «Always
   allow»** ([08-data-policy.md](08-data-policy.md)).
2. **Поиск по смыслу без сети.** Индекс кода и встроенная модель эмбеддингов (~320 МБ в
   памяти, выгружается при простое) лежат на машине. Вопрос по-русски находит код
   по-английски.
3. **Подтверждения по смыслу команды, а не по имени инструмента.** `git status` и
   `rg TODO` идут без карточки, `cargo test` спрашивает, `rm -rf`, `git push --force`,
   запись в `.bashrc` спрашивают всегда. Команда разбирается как дерево, а не поиском
   подстроки.
4. **Корпоративные условия с первого дня.** Свой CA для шлюза, свои заголовки запросов,
   ключи в системном keychain с шифрованным запасным файлом, повтор запроса только если
   провайдер не прислал ни байта.
5. **Экономия контекста — часть цикла.** Бюджет хода считается по весу инструментов,
   повторное чтение неизменившегося файла не пересылается, история сжимается сама, а
   промпт устроен так, чтобы кэш провайдера не сбрасывался каждый раунд.

## Возможности

### Агентный цикл

- **Три режима разговора**: Agent (читает, правит, запускает), Plan (только читает и
  пишет план), Ask (только отвечает). У каждого свой набор инструментов и свой системный
  промпт.
- **Пауза на подтверждении — это состояние, а не блокировка.** Ход останавливается с
  контрольной точкой из семи полей (история, раунд, бюджет, номер события, вызовы,
  чеклист, реестр прочитанного) и продолжается ровно с того места.
- **Указания во время хода**: сообщение, отправленное, пока агент работает, попадает в
  следующий раунд, не прерывая текущий.
- **Взвешенный бюджет**: дешёвая серия чтений живёт долго, дорогие поиски обрываются
  рано; число итераций — только страховка.
- **Дедупликация**: повторный вызов с теми же аргументами и тем же содержимым не
  пересылает результат второй раз.
- **Обрыв потока**: повтор — только если провайдер не отдал ни байта, иначе повторился бы
  уже выполненный инструмент. Если ответ модели оборвался посреди вызова, пометку об обрыве
  получает только недописанный вызов — успевшие выполнились нормально.
- **Чеклист (`todo`)** хранится у окна и приходит с каждым ходом; инструмент ничего не
  помнит сам.

### Работа с файлами

- `readFile` — целиком, диапазоном строк или **конспектом** (объявления и заголовки со
  строками вместо текста).
- **«Сначала прочитай»**: запись в файл, который агент не читал, или который изменился на
  диске после чтения, отклоняется с объяснением. Это ещё и защита от перетирания правок,
  сделанных пользователем параллельно.
- `editFile` — правки по якорю: якорь уникален, ищется в исходном тексте, пересекающиеся
  правки отвергаются, пакет применяется целиком или никак.
- **Предпросмотр до применения**: карточка подтверждения показывает дифф записи.
- Создание, удаление, перенос файлов и папок; `grep`, `listFiles`, `git status/diff/blame`.
- Все пути проверяются против корня открытой папки в одном месте.

### Команды

- `runCommand` с таймаутом, стримингом вывода в ленту и **убийством всего дерева
  процессов** (группа процессов), stdin закрыт.
- **Фоновые процессы**: dev-сервер или watcher запускается `background: true`, живёт между
  ходами; `readOutput` читает новый вывод, `stopProcess` останавливает. Вкладка Terminal
  показывает список, хвост вывода и кнопку Stop; о завершении процесса модель узнаёт сама.
- **Классификатор команд** на tree-sitter-bash — три ответа:
  - *без карточки* — только чтение: `ls`, `cat`, `rg`, `find` без `-exec`/`-delete`,
    `git log/diff/show/status`, при условии что всё на строке читает, нет записи в файл и
    не читается секрет (`.env`, ключи, `~/.ssh`);
  - *всегда карточка* (кроме режима Auto) — сеть (`curl`, `ssh`, `dig`, `git push`,
    `npm publish`), необратимое (`rm -rf`, `reset --hard`, `clean -f`, `branch -D`),
    системное (`sudo`, `systemctl`, `crontab`), запись в то, что запустится само
    (`.bashrc`, `.git/hooks/`, `authorized_keys`);
  - *обычная карточка* — всё остальное, включая то, что не удалось разобрать.
- Команды находятся везде: в пайпах, `$(…)`, `<(…)`, `if`, циклах, `sh -c "…"`.
  **Алиасы git** читаются из конфигурации: `git pf` → `push --force` спрашивает всегда.
- Карточка говорит, **почему** она появилась, если инструмент разрешён навсегда.

### Поиск и индекс

- Индекс открытой папки строится сам и следует за изменениями файлов (синк через 300 мс
  тишины). Семь языков через tree-sitter плюс Markdown; код режется по объявлениям.
- **Гибридный поиск** `semanticSearch`: имена символов, полнотекстовый поиск и векторы,
  объединённые через RRF. Качество замерено на 81 вопросе по трём репозиториям
  (MRR 0,45 → 0,55 после настройки).
- Встроенная модель — multilingual, словарь урезан до русского и английского, таблица в
  int8: ~320 МБ вместо ~1 ГБ, выгрузка через 10 минут простоя. Векторы — в SQLite,
  перебор 100 тыс. векторов — ~11 мс.
- Без модели поиск честно работает по словам и говорит об этом.

### Контекст

- Оценка стоимости следующего запроса по частям — инструкции, схемы инструментов,
  разговор — на счётчике в окне.
- **Сжатие истории**: заранее по порогу, по кнопке и **реактивно**, когда провайдер ответил
  «не влезает» (раунд сжимает историю и спрашивает снова, а не падает). В ленте остаётся
  заметка, что и сколько свёрнуто.
- **Кэш промпта**: у Anthropic — три точки `cache_control`; меняющийся чеклист вынесен из
  системного промпта в конец запроса, чтобы не сбрасывать кэш всей истории.
- **Thinking**: раунд, в котором модель думала, хранится целиком и уходит обратно без
  изменений; глубина рассуждений настраивается.
- **Правила проекта**: `AGENTS.md`/`CLAUDE.md` из корня папки — в промпте каждого хода, с
  переключателями.
- **Skills**: `SKILL.md` из `~/.atlas-desktop/skills`; в промпте — каталог, тело и файлы
  навыка модель загружает по требованию.

### Разговоры

- Лента хода: ответ модели как Markdown (таблицы, списки, блоки кода с номерами строк,
  подсветкой и копированием; подсветка — без WebAssembly, CSP не ослаблен), рассуждения, карточки инструментов с разворачиванием, заметки о
  сжатии, хуках, фоновых процессах.
- **Возвращение туда, где был**: при запуске открывается последняя папка и в ней последний
  чат; недавние папки — в меню сайдбара.
- **История**: каждый чат — отдельный файл; повреждённый или записанный новой версией
  приложения чат пропадает из списка один, остальные открываются.
- **Ветвление**: с любого своего сообщения — новый чат с разговором до него, сообщение
  возвращается в поле ввода. Исходный чат не меняется; сообщения, свёрнутые в сводку,
  не ветвятся (модель уже не видит того, что было до них).
- **Планы**: в режиме Plan агент пишет документ плана; его можно править во вкладке Plan и
  одной кнопкой передать в Agent.

### Расширения

- **MCP**: серверы stdio в формате `mcpServers` (конфиг Claude Desktop и Cursor
  вставляется как есть). Инструменты проходят тот же allowlist, подтверждения и лог, что и
  встроенные; только режим Agent; «Always allow» — на один инструмент, не на сервер.
  Упавший сервер перезапускается один раз за ход, упавший вызов не повторяется никогда.
  `PATH` берётся из login-shell — приложение, запущенное из Finder, находит `npx`.
- **Хуки** в формате Claude Code: `PreToolUse`, `PostToolUse`, `Stop`. Хук может запретить вызов,
  дописать замечание к результату или не дать ходу закончиться (не больше трёх раз
  подряд) — но разрешить вместо пользователя не может. Только глобальные; сломанный хук
  предупреждает и не блокирует.
- **Конфигурация из репозитория не исполняется**: ни `.mcp.json`, ни хуки из папки проекта
  не читаются — текст репозитория здесь данные, а не инструкции.

### Наблюдаемость и безопасность

- **Лог вызовов** включён по умолчанию, потому что содержимое файлов из записей вырезано;
  окно лога с фильтрами.
- **Отладочный лог запросов** к провайдеру — выключен по умолчанию и предупреждает, что
  пишет разговоры целиком.
- **Ключи**: системный keychain; если он недоступен, приложение это обнаруживает и уходит
  в шифрованный файл, а не в молча теряющую секрет заглушку.
- **«Where your data goes»** в настройках — провайдер, включённые MCP-серверы, хуки, лог
  запросов по текущей конфигурации.

## Чем отличается — подробнее

| Решение | Как у нас | Почему |
|---|---|---|
| Где живёт логика | В Rust-ядре; окно только рисует и хранит транскрипт | Цикл под тестами без окна; контекст и сжатие не зависят от UI |
| Провайдер | Любой OpenAI-совместимый или Anthropic, свой хост, CA и заголовки | Корпоративный шлюз — основной сценарий, а не исключение |
| Эмбеддинги | Встроенная модель, без сети, ru+en | Код не уходит к стороннему провайдеру эмбеддингов |
| Подтверждения | По разбору команды; опасное спрашивает всегда | «Always allow» разрешает работу, а не `rm -rf` |
| Запись файлов | Только после чтения, с проверкой хэша | Параллельная правка пользователя не перетирается |
| Конфиг из репозитория | Не исполняется | Открыть чужой репозиторий безопасно |
| Хуки | Формат Claude Code, только запрет | Хук не может расширить allowlist молча |
| Данные | Политика + тесты-сторожа + CSP | Нарушение ловится до релиза, а не в аудите |
| Отказоустойчивость хранения | Файл на чат, версия формата в записи | Одна порча — один чат, а не вся история |

## Чего нет (осознанно или пока)

- **Песочницы команд** (CA-4.7). Что делают `python -c`, скрипты, тесты и `make`, не видно;
  при «Always allow» они идут без разбора, в режиме Auto — всё.
- **Отката файлов** к точке ветвления или сообщения: ветвится только разговор, файлы
  остаются как есть (откатывать — через git).
- **Памяти между разговорами** (F-6.7) — отложена.
- **Сабагентов и параллельных веток исполнения**.
- **CLI, облака, аккаунтов, шаринга сессий** — продукт десктопный и локальный; копия
  приложения одна — второй запуск поднимает окно первого.
- **MCP по HTTP** — только stdio.
- **Хуков уровня проекта** и JSON-ответов хуков.
- **Ввода в фоновый процесс** — вкладка Terminal только наблюдает.
