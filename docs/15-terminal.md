# Терминал пользователя

Рабочий документ фичи: свой терминал в приложении, как нижняя панель Terminal в Claude
Code Desktop. Шелл пользователя в настоящем PTY, xterm.js на экране, а потом агент,
который этот экран читает.

Документ живёт до конца фичи: решения, этапы, прогресс, журнал.

## Исходная точка

- Вкладка Terminal уже есть, но это список фоновых процессов агента
  (`components/panes.tsx`, `TerminalPane` → `ProcessList`). Ввода в них нет, и это
  записано в [09-product.md](09-product.md) как потолок.
- Нижний док размонтируется при закрытии (`{bottomTab && <AsidePanel …/>}` в `App.tsx`).
  Значит, PTY живёт в бэкенде, а вывод, накопленный без экрана, отдаётся заново при
  следующем подключении.
- Бэкенд пока держит одну папку (F-8 не начат), и `workspace_open` останавливает фоновые
  процессы. Терминал живёт по тому же правилу. Когда F-8.3 разнесёт процессы по папкам,
  терминалы уходят вместе с ними.

## Решения

| Вопрос | Решение | Почему |
|---|---|---|
| PTY | Крейт `portable-pty` (из WezTerm, MIT) | Unix-PTY и ConPTY на Windows за одним API. `tauri-plugin-shell` и `std::process` дают только pipes: vim, htop, readline и цвета без TTY ломаются |
| Плагин `tauri-plugin-pty` | Не берём | Свой слой — ~300 строк и ложится в `infra/` со sink по правилам слоёв; плагин обходит их и тащит свой JS API |
| Шелл | Login-шелл пользователя (`CommandBuilder::new_default_prog`: `$SHELL`, `argv[0]` с `-`) | Это его терминал: его zsh, его функции. Агентский `runCommand` остаётся на `/bin/sh` — там воспроизводимость важнее |
| Окружение | `TERM=xterm-256color`, `COLORTERM=truecolor`, `PWD` = папка, `LANG=en_US.UTF-8`, если не задан; `TERM_PROGRAM` родителя убирается. `PATH` не трогаем | Приложение из Dock получает пустой `LANG` — zsh ломает UTF-8; `TERM_PROGRAM` от iTerm при `tauri dev` соврал бы программам о терминале; унаследованный `PWD` назвал бы папку, откуда запущено приложение. `PATH` login-шелл строит сам из профиля — `login_path` нужен только процессам без него |
| Вывод на фронт | `tauri::ipc::Channel` с сырыми байтами, по подключению | Поток данных, а не сигнал перечитать — AGENTS.md это разрешает. Канал живёт, пока вкладка на экране, как любой listener |
| Частота | Не чаще кадра (16 мс) на терминал; первый кусок после тишины — сразу | Эхо клавиши без задержки, а `yes` — 60 сообщений в секунду, не тысячи. Троттлинг там, где источник |
| Ввод | Отдельный поток-писатель на терминал, очередь | Запись в PTY может заблокироваться (большая вставка, программа не читает) — синхронная команда Tauri тогда повесила бы окно. `async` перемешал бы нажатия |
| Список и выход шелла | Событие `terminals:changed { id }` — сигнал перечитать список | Как `processes:changed` |
| Накопленный вывод | Кольцо байт на 512 КиБ, обрезка по началу строки | Повторное подключение рисует экран заново; обрезка по `\n` не начинает с середины escape-последовательности |
| Закрытие | `SIGHUP` шеллу; то, что у него на переднем плане, получает `SIGHUP` от ядра, когда шелл — управляющий процесс терминала — завершается | Как закрытие окна терминала. Отдельный сигнал группе переднего плана был лишним — это показала мутация |
| `runCommand` агента | Остаётся на pipes | Там нужны таймаут, лимит вывода и код выхода, а не TTY |

## Этапы

### A. Бэкенд PTY

- `domain/terminal.rs` — типы: `TerminalInfo`, `TerminalState`, `TerminalSize`,
  `TerminalChanged` и sink, `TerminalError` (`thiserror`), кольцо `Scrollback`.
- `infra/terminal.rs` — `Terminals`: открыть, список, подключить/отключить sink вывода,
  писать, менять размер, закрыть, закрыть все. Потоки на терминал: читатель, сборщик
  кадров, писатель, ожидающий выхода.
- `commands/terminal.rs` — `terminal_open`, `terminal_list`, `terminal_attach` (с
  `Channel`), `terminal_detach`, `terminal_write`, `terminal_resize`, `terminal_close`;
  канал `terminals:changed`. Регистрация в `generate_handler!`; `close_all` при
  `workspace_open` и при `RunEvent::Exit`.
- Тесты (unix): ввод доходит и возвращается, `cwd` — папка, `stty size` видит ресайз,
  подключение отдаёт накопленное, чужой `detach` не отключает, выход шелла виден в
  списке и сигналится, закрытие убивает то, что шло в шелле, поток вывода сжат в кадры.
  Мутации.

**Итог этапа A.** 23 теста (`cargo test terminal`), весь `cargo test` зелёный. Настоящий
login-шелл проверен разово, не тестом (тест не должен исполнять чужой `.zshrc`):
`-zsh`, `LANG=en_US.UTF-8`, `pwd` — папка, эхо и escape-последовательности приходят
сырыми.

**Мутации: 25, пойманы 23.** Ломали: проверку нулевого размера; кольцо — обрезку, поиск
начала строки, его предел, сам перевод строки; повтор накопленного при подключении;
ключ `detach`; отказ писать в закончившийся шелл; склейку кадров и паузу между ними;
накопление вывода; `cwd`, `TERM`, `TERM_PROGRAM`, `LANG`; убийство шелла; код при
сигнале; сигналы об открытии, закрытии и `close_all`; сырые байты в канале; проверку
размера в команде.

Не пойманные сразу:
- *Без `SIGHUP` группе переднего плана* — выжил, потому что это делает ядро. Код удалён.
- *Шелл не убивается* — выжил, пока был жив предыдущий: `sleep` умирал от лишнего
  сигнала, а шелл — от EOF при закрытии писателя. После удаления пойман тестом
  `closing_ends_what_runs_in_it`.
- *`hang_up` и по уже прибранному шеллу* — не наблюдается без переиспользования pid,
  которое тест вызвать не может. Защита от сигнала чужому процессу оставлена по
  рассуждению.
- *slave остаётся до конца `spawn`* — эквивалентная: он и так уходит в конце функции;
  явный `drop` — для читателя.

### B. UI

- `bun add @xterm/xterm @xterm/addon-fit @xterm/addon-web-links`. WebGL — когда DOM-рендер
  начнёт тормозить на больших логах; тогда же `onContextLoss`.
- `src/lib/terminal.ts` — обёртки и `Channel`, единственное место с `invoke`/`listen`.
- `src/hooks/useTerminal.ts` — подключение, пока вкладка на экране; список по
  `terminals:changed`.
- `src/components/TerminalView.tsx` + `.css` — xterm, `onData` → write, `ResizeObserver` →
  fit → resize; тема из токенов (`--term-*` ANSI-палитра в `tokens.css` для обеих тем),
  шрифт `--font-mono`, масштаб `--font-scale`; сочетания приложения мимо шелла; ссылки
  через opener.
- `TerminalPane`: вкладки шеллов и «+», фоновые процессы — вкладка «Processes».
  Ctrl+` показывает и прячет панель.
- `FolderSwitchDialog` называет и открытые терминалы: переход в другую папку их закроет.
- Тесты хука и обёрток с замоканным `invoke`.

### C. Агент видит терминал

- Крейт `vt100` в `infra/terminal.rs` получает те же байты: экран, alt-screen, scrollback.
- `readTerminal` — последние строки экрана, без подтверждения; в модель как данные.
- `runInTerminal` — напечатать команду в терминал пользователя, через тот же approval
  gate и `command_risk`, что `runCommand`.
- «Добавить в чат»: выделение в xterm прикрепляется к композеру с пометкой терминала.
- При повторном подключении — снимок экрана из `vt100` (`contents_formatted`) вместо
  сырых байт.

### Не делаем, пока не попросят

Поиск (`addon-search`), WebGL, фоновые процессы агента через xterm, восстановление
шеллов после перезапуска.

## Потолки

- **Windows**: шелл — `%ComSpec%` (так решает `new_default_prog`); закрытие —
  `TerminateProcess` шелла, его дети могут пережить (тот же потолок, что у
  `process_runner`, 05-gaps §5.4). Unix-тесты этого не покрывают.
- **Шелл, который перехватывает `SIGHUP`**, закрытие не убьёт — эскалации до `SIGKILL`
  нет.
- **Лимита на число терминалов нет.**
