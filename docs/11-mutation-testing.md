# 11. Мутационная проверка тестов

Так тесты проверялись на всём переносе, с F-0.4 и до этапа 7. Документ описывает метод
и инструмент; отчёты по фичам лежат в [06-port-plan.md](06-port-plan.md) строками вида
«**Мутации: шесть, все пойманы.**».

## Правило

**Зелёный `cargo test` не значит, что код проверен — он значит, что тесты не падают.**
Проверен код тогда, когда сломанная версия падает. Поэтому у каждой новой фичи на бэкенде
(и у нетривиальной логики на фронте) последний шаг — сломать собственный код по одной
правке за раз и убедиться, что каждую поломку кто-то ловит.

Выжившая мутация — это **недостающий тест**, а не неудачная мутация. За перенос такие
находки трижды оказывались настоящими дырами в продакшен-коде, а не придирками к тестам.

## Что считать мутацией

Не «все мутанты, которые породит инструмент», а по одной на каждое правило, которое тест
обязан охранять. Из плана видно, что на фичу выходило четыре–семь. Что мутировалось:

| Вид | Пример из переноса |
|---|---|
| Снятая проверка | `..` в пути; сверка purpose в associated data; проверка пересечения правок |
| Ослабленное условие | «видела целиком» → «видела хоть что-то»; лимит до фильтра вместо после |
| Возврат умолчания | нечитаемый `Retry-After` → ноль вместо «подсказки нет» |
| Выброшенная ветка | инструмент, выпавший из разбора; поле, выпавшее из схемы |
| Подмена порядка/режима | последовательное применение правок вместо пакетного |
| Снятая уборка ресурса | нет группы процессов при убийстве; сигнал ребёнку вместо группы |
| Обнулённый предел | таймаут `0`; снятый потолок повтора; ожидание блокировки SQLite убрано |
| Утечка в лог/на диск | ключ открытым текстом; снятый гейт отладочного лога |

Мутация обязана быть **правдоподобной ошибкой**: так пишут, когда торопятся. Правка,
которую никто никогда не сделает, ничего не проверяет.

## Исходы

- **Пойман** — упал конкретный тест. Прогон печатает его имя: «поимка», под которой не
  падает ни один тест, — баг прогона, а не убийство.
- **Выжил** — дыра. Тест пишется сразу, до перехода к следующей фиче, и мутация
  повторяется: она должна начать падать.
- **Эквивалентная** — поведение не изменилось (начальное значение поля, которое всё равно
  перетирается). Записывается в отчёт как эквивалентная и не чинится.
- **Не собрался** — ни убийство, ни выживание. Пустой вывод красных тестов легко принять
  за поимку, поэтому прогон смотрит на текст сборки, а не только на код возврата.
  Мутация переформулируется.
- **Завис** — считается пойманным. Случай реальный: мутант «не убивать группу процессов»
  заставил `StdioServer::drop` ждать вечно, и прогон встал на 29 минут.

## Уроки, которые повторялись

**Мутация падает не на том тесте, для которого писалась** (F-1.3, F-1.6). Тест, который
мутацию *проходит*, охраняет не то, что вы думали: `edits_are_independent_of_their_order`
на непересекающихся правках не отличает пакетное применение от последовательного — их
различает только случай, где `new` одной правки является якорем другой. Пока мутация не
названа, этого не видно.

**Тест может охранять фикстуру, а не код.** Сторож формата лога звал `append` напрямую —
то есть проверял тестовую сборку записи, а не `log_request`, который правят. Мутация
выжила. Лечится переписыванием теста через публичную точку входа.

**Мутация находит ошибки и в тестовых дублях.** Дубль «связка недоступна» отказывал и
зонду тоже, то есть моделировал «связки нет вовсе»; настоящий macOS ведёт себя иначе.
Пока дубль врал, защита от перевыпуска ключа проверялась понарошку.

## Инструмент

[`scripts/mutate.py`](../scripts/mutate.py) — одноразовый план на прогон, JSON,
запускать из корня репозитория:

```bash
python3 scripts/mutate.py plan.json      # до первого не-убийства
python3 scripts/mutate.py plan.json -k   # дойти до конца
python3 scripts/mutate.py plan.json --only 3
```

```json
{
  "test": "cargo test command_risk",
  "cwd": "src-tauri",
  "timeout": 900,
  "mutants": [
    {"file": "src-tauri/src/domain/command_risk.rs",
     "find": "if program == \"sudo\" || program == \"doas\"",
     "replace": "if program == \"doas\"",
     "note": "sudo больше не считается поднятием прав"}
  ]
}
```

`find` должен встречаться в файле ровно один раз, иначе прогон не начнётся. Фильтр тестов
(`cargo test command_risk`, `bun test src/__tests__/Dropdown.test.tsx`) берётся узкий: гонять
всё дерево на каждого мутанта незачем — но фильтр должен покрывать **все** тесты, которые
могли бы поймать эту правку.

Что прогон делает сам, и почему это не обсуждается:

- **Базовый прогон до мутаций** и отказ работать на красном дереве — иначе «поймано» будет
  печататься на тестах, которые падали и без мутации.
- **Таймаут на каждого мутанта**, убийство всей группы процессов, зависание засчитывается
  пойманным.
- **Небуферизованный вывод.** В тот самый 29-минутный прогон буферизация унесла с собой все
  результаты, когда его остановили.
- **Оригиналы вне репозитория**, восстановление `cp`-ом. `git checkout` снёс бы и остальные
  правки в дереве, а они там есть почти всегда.

Тесты `#[ignore]`-нутые (модель эмбеддингов) в мутационные прогоны не входят: полгигабайта
и секунды на мутанта. Логика вокруг них проверяется тестами, которые модель не грузят.

## Что писать в отчёт

В [06-port-plan.md](06-port-plan.md), в блоке фичи, одной строкой: сколько мутаций, все ли
пойманы, и перечисление — что именно ломали. Отдельным абзацем — всё, что не поймано
сразу: выжившая мутация, тест, который её закрыл, и эквивалентные. Это единственная часть
отчёта, которую кто-то потом читает.
