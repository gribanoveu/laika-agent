# Куда уходят данные (CA-12.6)

**Правило:** содержимое файлов рабочей папки уходит с машины только к провайдеру модели,
которого выбрал пользователь. Всё остальное, что может вынести данные наружу, либо
настраивает сам пользователь, либо спрашивает перед каждым разом. Где этого обещать нельзя,
документ так и говорит.

## Выходы

| Куда | Что уходит | Кто решает | Чем держится |
|---|---|---|---|
| **Провайдер модели** (OpenAI-совместимый или Anthropic, хост из настроек) | Промпт, история, результаты инструментов — в том числе содержимое прочитанных файлов; сводка при сжатии истории идёт туда же | Пользователь выбирает провайдера и хост | Единственный сетевой код приложения — `infra/llm_providers/` и `infra/http_agent.rs`; тест `data_policy::only_the_provider_opens_connections` |
| **MCP-серверы** | Аргументы вызова, которые выбрала модель, — могут включать текст файлов | Пользователь добавляет сервер в `mcp.json` и включает его | Каждый вызов спрашивает (Always allow — на один инструмент, не на сервер); только в режиме Agent. Что сервер делает с данными дальше — его дело, не наше |
| **Хуки** | JSON события: `tool_input` и `tool_response` — то есть и содержимое файлов | Пользователь пишет `hooks.json` | Только глобальные; хуки из репозитория не читаются. Это команды пользователя на его машине |
| **Команды агента** (`runCommand`) | Что угодно: у shell есть сеть | Карточка подтверждения | Команда только для чтения идёт без карточки (`ls`, `rg`, `git status`…) — но не если читает секрет: `.env`, ключи, `~/.ssh` попали бы в разговор. Команда, уходящая в сеть (`curl`, `ssh`, `dig`, `git push`, `npm publish`…), и необратимая (`rm -rf`, `git reset --hard`, `sudo`, запись в `.bashrc` или `.git/hooks`) **спрашивает даже при Always allow runCommand** (`domain::command_risk`). В режиме Auto не спрашивает ничего — это и есть смысл Auto |
| **Окно приложения** | Ничего | — | CSP в `tauri.conf.json`: только само приложение и IPC; внешний `fetch`, `<img>`, шрифт отклоняются. Тесты `the_window_sends_nothing_itself`, `the_window_may_reach_nothing_but_the_app` |

## Что остаётся на машине

Всё в `~/.atlas-desktop/`, права — только владелец:

- `chats/` — разговоры целиком, включая содержимое файлов в результатах инструментов;
- `index/` — индекс рабочих папок (фрагменты кода и вектора; эмбеддинги считает встроенная
  модель, **без сети**);
- `tool_calls.db` — лог вызовов, содержимое файлов из записей вырезано (CA-12.1);
- `logs/llm.jsonl` — сырые запросы к провайдеру, **выключено по умолчанию** (CA-12.2);
  включённый пишет на диск всё, что ушло провайдеру;
- `llm_credentials.enc`, `settings.json`, `mcp.json`, `hooks.json`, `skills/`.

Телеметрии нет. Зависимостей, существующих ради отправки данных (HTTP-клиенты кроме `ureq`,
Sentry, PostHog и подобные), нет — `data_policy::no_dependency_exists_to_send_data_elsewhere`.

## Чего политика не обещает

- **Разбор команд — не песочница.** `python -c`, `node -e`, скрипт из репозитория, цель
  `Makefile`, `npm install` с postinstall-скриптом ходят в сеть, и из командной строки этого
  не видно. Настоящая граница — сетевая песочница команд (CA-4.7), её нет.
- **Always allow runCommand** разрешает всё, кроме распознанных сетевых и необратимых
  команд. Режим
  **Auto** разрешает всё.
- **MCP-сервер** получает то, что модель положила в аргументы, и дальше мы его не видим.
- **Провайдер** хранит и использует запросы по своим правилам.

## Как это не сломать

Новый сетевой код, зависимость или источник в CSP падает в тестах `data_policy`. Если выход
нужен на самом деле, сначала добавляется строка в таблицу выше, потом исключение в тест.
